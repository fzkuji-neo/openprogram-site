Web 运行时可靠性与性能设计

本文统一记录 Web 页面刷新、会话加载、WebSocket 消息分发、后台错误展示、EventBus 通知、异步 Job 状态、静态资源加载和本地状态目录的已验证问题，并给出相互兼容的目标合同、任务边界和量化验收标准。

受众：Runtime / Server / Web 维护者 状态：TASK 1 partial；TASK 3 complete；TASK 6 complete；其余任务待执行 证据：源码审计、真实会话测量、浏览器测量、定向测试
主结论：持久错误状态尚未实现、刷新时重复发送完整会话，以及 EventBus notify 可能同步阻塞或丢失仍是 P0。命令异常隔离和首组管理 action 迁移已经完成两切片，但其余旧错误路径与恢复合同仍待实现。WebSocket 广播无界问题已有完成规格审查、质量审查和完整 Python gate 的 TASK 3 实现。TASK 6 已完成本地依赖、静态压缩、延迟表面切分和资源预算实现，并通过两类审查、完整 Python gate、默认 App 可视验收和本地 browser trace。
范围边界：本文不修改 Agent 推理逻辑、DAG 存储语义、模型提供商协议、权限模型或多用户身份模型。已有专题文档继续负责各自的详细语义；本文只定义它们在 Web 运行时可靠性和性能方面必须共同满足的合同。

04

统一错误合同与前端展示

“后台报错前端必须显示”定义为：所有影响用户请求、持久状态、后台任务或可恢复操作的失败都必须进入可观察错误记录。它不要求把每个内部降级或重试都显示成 Toast，也不允许把 traceback、文件内容或凭据发送到浏览器。下列 schema 是唯一最终 wire 合同；TASK 1 服务端已为公共 dispatcher 和首组管理 action 生成完整字段、在发送前记录，并实现 principal-scoped list、exact-ID acknowledge 和多窗口 recovery。前端 hydration、展示和其余错误源仍按后续切片实现。

// WebSocket envelope；nullable 字段使用 null，不省略语义必需字段
{
  "type": "operation_error",
  "data": {
    "error_id": "err_opaque_unique_id",
    "request_id": "client_request_id_or_null",
    "scope": "session | job | settings | channel | agent | transport | system",
    "code": "stable_machine_code",
    "message": "safe user-facing summary",
    "action": "safe_action_or_null",
    "session_id": "session_id_or_null",
    "operation_id": "action_job_execution_id_or_null",
    "retryable": false,
    "severity": "info | warning | error | fatal",
    "correlation_id": "opaque log lookup id",
    "occurred_at": "ISO-8601 UTC"
  }
}
错误合同字段/状态唯一语义
request_id由客户端为请求/响应 action 生成；成功或失败必须回传同一值并结束 pending。operation_id 标识服务端实体，不能代替 request ID。
error_id每次失败唯一。Toast 去重键为 scope + code + session_id + operation_id，5 秒内相同键只显示一次；错误记录仍分别保留。
UserErrorStore使用当前 profile 下独立 SQLite 文件，按已认证 principal 隔离；创建时间起最多保留 7 天且每个 principal 最多 1,000 条。开放记录按 occurred_at、error_id newest-first 严格分页，确认操作按 principal + exact error_id 事务性幂等关闭。发送必须发生在事务提交之后；记录失败时不发送伪 durable envelope，而关闭连接并要求 state recovery。
severityinfo 只进入诊断；warning 显示局部 degraded 状态；error 显示卡片和一次 Toast；fatal 显示持久阻断状态并停止自动重试。
生命周期请求成功只结束对应 request_id 的 pending。acknowledge_user_error 在请求连接内依次发送带同一 request_id 的 user_error_acknowledged 和 {type:"operation_recovered", data:{error_ids:[...], scope, operation_id, occurred_at}}；持久关闭后，其他同 principal 窗口独立接收同一 recovery，跨连接不承诺相对顺序，请求连接发送失败也不得阻止其他窗口恢复。服务器必须列出要关闭的具体 error_id，前端不得按模糊 code 批量关闭；重复确认可再次发送同一 exact-ID recovery 以使窗口收敛，数据库关闭保持幂等。用户确认或实体删除也只关闭明确 ID；普通后续成功不能隐式清除不相关错误。
Job 失败job_status(status=errored) 是 Job 状态的唯一 wire 事件，前端由它生成 error-store 记录；不得再为同一失败发送第二个 operation_error。operation_error 只用于 Job action 请求本身失败。

会话加载与刷新设计

目标是让首屏成本由当前可见内容决定，而不是由整个会话历史决定。持久化仍以 SessionDB/DAG 为准；Web wire 只传页面当前需要的投影。

阶段返回内容触发条件缓存键
Session manifest标题、状态、head、revision、当前链 ID、计数、功能状态、错误摘要。切换会话或无有效 manifest。session_id + revision
Viewport messages当前可见链尾部消息和必要的 compaction/attach 引用。首屏或滚动到未加载范围。session_id + head_id + cursor
Graph summary节点 ID、边、角色、状态和最小标签，不包含消息正文与工具结果。用户打开 DAG 或分支面板。session_id + graph_revision

协议量定义保留与回退
session_revision每个 session 单调递增的整数。一次 SessionDB/DAG 原子提交只增加一次；manifest、message header、Graph summary 和持久错误都标记其读取 revision。永久随 session 持久化。客户端 revision 高于服务端或 schema 不兼容时拒绝 delta 并返回新 manifest。
stream_seq每个运行中 message/job 独立单调递增；只描述尚未形成持久提交的 text/tree/progress 增量。当前 worker 每实体保留最近 256 个 delta 或 15 分钟，以先达到者为准。worker 重启把未完成实体持久标记 error/aborted，客户端随后执行 manifest recovery。
delta journal由持久提交生成的 from_revision → to_revision projection change；不保存完整正文副本。内存保留最近 512 次提交或 15 分钟。缺口超过保留范围时返回 manifest + 有限 viewport。
viewport cursor稳定二元组 (created_at, message_id)，按当前 head 链逆序分页；首屏最多 100 条且未压缩 JSON 最多 512 KiB，以先达到者为准。向历史方向分页；head 改变时 manifest 给出新 cursor。单条消息超过剩余预算时只返回 header、摘要和 detail marker。
detail cursor单节点/工具结果每次最多 1 MiB 未压缩内容；更大结果按 UTF-8 安全边界分块并返回 next cursor。每次读取都重新执行 session/node/caller 授权；不得通过 cursor 跨节点或跨 session。
计算与发送的分离边界

同步线程读取不可变 SessionDB 快照、建立 ID 索引、计算当前链与 Graph summary，并返回普通数据对象。异步 handler 在发送前再次校验 session revision；若期间发生写入，发送 manifest 后追加 delta，或放弃旧快照重新读取。线程内不得直接操作 WebSocket。

需要删除的重复计算

预先创建 id → insertion_index，替代排序中的 all_msgs.index；兄弟分组按 predecessor 一次建立；同一请求只读取一次 session row；Graph summary 与消息正文分开序列化。

大字段与兼容

保留当前 32 KiB 工具结果 marker 和 get_full_tool_output 权限检查。进一步把 context tree、runtime blocks、Graph node content 和附件 metadata 纳入按需读取。旧客户端仍可请求旧 action，但服务端需要设置硬载荷上限并在超过时返回升级提示，而不是继续生成无界帧。

06

WebSocket 队列、顺序与恢复

浏览器标准 WebSocket API 不提供自动背压，因此服务器必须限制自己的发送队列。每个连接由一个 sender task 顺序发送，生产线程只执行线程安全的 enqueue。

帧类别示例队列规则溢出行为
不可丢终态error、question、chat final、job terminal、ack、permission result保持顺序，不覆盖，不跨 session 合并。无法在预算内排队时关闭连接并标记需要 state recovery；不得静默丢弃。
可合并增量text/thinking delta、tree update、progress、context stats按 session + entity + type 保留最新或合并相邻文本。删除被更新取代的旧增量，并记录 coalesced 计数。
快照sessions list、branches、settings、graph summary同一 key 只保留最新未发送快照。替换旧快照；不影响终态。
控制pong、auth/status、reload required小型独立预算，防止被大消息完全延迟。认证或协议错误立即关闭；pong 可丢弃旧值。

队列上限与关键预留

每连接限制 256 帧或 4 MiB，以先达到者为准；其中 64 帧和 1 MiB 只供不可丢终态。关键帧入队前先清除可合并增量，不能占用普通快照的旧版本。

发送所有权

只有 sender task 调用 ws.send_text。断开时取消 sender、释放队列并注销 focused session；其他线程不保留 WebSocket Future。

重连

指数退避并加入随机抖动；页面重新可见或用户明确重试时可提前触发。成功后先恢复协议状态，再恢复会话投影。

观测指标

记录 queue_frames、queue_bytes、oldest_age、coalesced、send_failures、disconnect_reason 和 recovery_mode，不记录帧正文。

关键帧恢复合同：source 在 enqueue 前持久化 chat final、job terminal、用户可见 error、question 和 permission request。所有用户可见 error 同时写入有界 UserErrorStore，按 error_id 查询，最多保留 1,000 条或 7 天；session manifest 只携带相关未关闭 ID，重连通过 list_user_errors(cursor) 读取详情。transport close 由客户端根据 close/timeout 本地生成，不依赖服务端错误帧。chat ack 只在用户消息落盘后发送；其他 request ack 必须能通过 request_id 幂等查询或重放。若关键预留仍满，服务器关闭该连接并标记 state_recovery_required；客户端重连后从 manifest、UserErrorStore、pending-question registry、Job store 和 request result 查询恢复，不能依赖未发送的内存帧。
MDN WebSocket

标准 WebSocket API 不提供自动背压；继续使用兼容性最好的 WebSocket，但必须在应用层限制队列。

MDN bufferedAmount

客户端可用 bufferedAmount 监测未发送字节，但该值不能替代服务端每连接队列和恢复协议。

Python asyncio.Queue

采用正数 maxsize 的 FIFO 队列；跨线程入口使用 event loop 的线程安全调度，不直接跨线程操作 Queue。

EventBus 执行模型与日志

EventBus 保留两种明确语义：gate 是同步决策；notify 是异步观察。二者不能共用“当前线程直接调用 handler”的执行方式。

属性GateNotify

失败维持现有 fail-open，并写结构化警告和 gate 结果。隔离消费者；重试只由消费者策略决定；不得静默跳过。
顺序注册顺序。同一 session + entity 有序；不同 key 可并发。
背压不排队；超过预算时跳过剩余 gate 并记录。有界队列；关键事件不能被普通遥测占满。

关闭与重启正常关闭最多排空 2 秒；剩余 notify 记录 shutdown loss marker。关键业务状态在 emit 前持久化，重启后由各 store 的 recovery 扫描恢复，不把 EventBus 当 durable queue。

Bounded session history

Session loading separates the latest transcript page from older history. Pages retain their captured branch head and a stable oldest-message cursor. A page contains complete display rows and their caller descendants, with at most 50 top-level rows and a 512 KiB target serialized budget. One indivisible larger row is returned alone. Paging never edits stored history or model context. Historical reads do not change focus, live session head, execution state, or question replay.

Codex separates thread metadata, turns and items through paginated history APIs. DeepSeek Harness exposes message-aligned pages and sequence cursors. This implementation adopts stable branch snapshots, backward paging and incremental live updates; it retains OpenProgram's existing branch graph and execution recovery contracts. It does not introduce another session store or change model compaction.

Duplicate promoted fields are omitted from the wire-only extra object. Existing tool-output previews retain their authorized full-output expansion. Logical history and graph responses larger than the transport frame budget are sent as ordered, awaited fragments; the client reconstructs a complete response before dispatch, preserving first-fragment order with subsequent live notifications. Deferred responses share a per-connection budget of 64 million UTF-16 code units, eight incomplete transfers and 1,024 logical responses. This handles a single large row without silently dropping data or increasing the 4 MiB sender queue. Ordinary live updates continue independently. Fragment buffers belong to one connection and are discarded on disconnect. Reconnect loads a fresh recent page and uses existing execution recovery.

The client prepends older rows by stable identity without replacing newer live content or moving the selected conversation. Page requests capture the current load generation and are ignored after a reload, branch switch or socket replacement. An unavailable cursor produces an explicit retryable error instead of a reconnect loop. Scroll position remains anchored when older messages are inserted. The graph remains complete for existing branch and compaction controls; server-side history projection still scans the captured session. Storage indexing and lazy graph rendering are separate optimizations, not claimed here.

Acceptance: the copied failing session opens without queue overflow; every logical page retains exact content and caller ownership; page frames stay bounded, including Unicode and a single oversized row; cursor exhaustion loses or duplicates no messages; stale responses cannot overwrite live/newer state; disconnection releases partial buffers; branch, compaction, tool expansion and execution recovery remain functional. The installed App retrieves all 26 original display rows in five pages without duplicates, reordering or disconnects; the largest observed transport frame is 51,564 bytes. Reload and heartbeat remain operational.

Long-session layout and loading

The bounded history protocol separates transport size from transcript length. Long sessions also require stack-safe graph construction: the depth pass previously followed every ancestor for every node and recursively visited the conversation chain. A 1,500-node linear conversation exceeds Python's recursion limit before its first page can be delivered.

Graph depth now uses a memoized parent-chain classification followed by iterative preorder traversal. Nodes whose parent path enters a cycle remain independent roots, preserving the existing defensive behavior. Forks, retries, spawned branches and call children retain their current row order and offsets. Parent classification visits each node once; traversal does not depend on the Python call stack. Follow-up normalization indexes replies once. Lane column placement maintains per-lane widths and the largest occupied column rather than rescanning previously placed nodes.

Session message aggregation and byte-budget page preparation execute outside the event loop, while awaited WebSocket sends remain on the owning loop. Branch graph construction also executes outside that loop. Snapshot and incremental event ordering remain unchanged. The existing in-memory session index remains authoritative for reads; this change introduces no persistent cache, schema migration or history deletion.

Acceptance uses the public graph builder and session-loading handler with long chains, wide fork sets and invalid cycles. Small-graph output must match existing layout contracts, and a 10,000-node transcript must load a bounded recent page without recursion failures. Full graphs and initial store indexing remain proportional to session size; this work does not claim constant-memory storage or indexed transcript projection. The Codex and DeepSeek references in the bounded-history section continue to define the paging comparison.

Public layout and session-loading tests cover a 10,000-node chain, wide forks and invalid cycles; complete graph output and bounded transcript pages are preserved. The combined verification and installed-App long-history replay pass. Initial graph and store memory still grow with session size.
