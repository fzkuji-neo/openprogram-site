查看和编辑 Memory#

打开 History → Memory，再选择主题。主题和 Core 源记录默认显示预览，点击“编辑” 修改 Markdown。页面没有 Save、Saved 或 Changes 控件。

每次输入立即保留在当前浏览器的草稿存储中，并自动提交文件写入。写入按顺序执行， 旧请求不会覆盖新输入。使用 Cmd+Z 或 Ctrl+Z 撤销，Cmd+Shift+Z、Ctrl+Shift+Z 或 Ctrl+Y 重做；App 保持打开时，自动保存不会清除该文档的撤销记录。

文件保存与 Git 历史分开处理。服务器默认每 5 分钟将手动修改记入历史，调度误差最多 15 秒；计时不会因关闭编辑器而停止，服务器重启后也会继续处理。后台 Memory 操作 仍可生成自己的提交。开始一段手动编辑前的版本也会保留。

“历史”按从新到旧的顺序列出版本，显示本地日期和时间。选择版本即可查看增加和 删除的行。点击“恢复此版本”恢复该文档：先记录当前状态，再为恢复操作创建一条 新记录。已有历史不会被删除，因此也可再次选择其他版本。恢复仍会校验来源引用， 不会破坏其他 Memory 文档指向该文档的链接。

保存被拒绝或发生冲突时，草稿会保留并显示原因。“查看最新版本”会在历史面板中 比较最新文本与草稿；“用当前草稿替换最新版本”按刚查看的版本重新保存。如果此时 又发生其他修改，仍会拒绝覆盖。

来源脚注打开只读来源视图。如果本地原会话已删除，会显示“原会话已删除”，不再 展示旧来源原文。删除时不会额外复制来源文档，已提取的记忆继续保留。这个来源可用性 规则不会重写现有 Memory Git 仓库。归档只隐藏会话，保留内容和链接，不会因为超过 某个期限或容量而自动删除。
